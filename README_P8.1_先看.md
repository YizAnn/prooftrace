# 寻证 ProofTrace · P8.1 设计与业务整合

2026-11-21 · 基于 P8 Creative Workspace 进行的增量调整

## 打开方式

Windows 电脑上解压完整项目，运行 `启动ProofTrace.cmd`（Node.js 18+）。待本地服务启动后访问自动弹出的地址。首页沿用 P8 的证据场风格；进入工作区后可以测试侧边导航、研究、资料解析、证据、技术评价与专家规则。

`index_p8_backup.html` 和 `index_p72_backup.html` 分别为 P8 和 P7.2 旧版备份；当前网站入口仍是 `index.html`。真实 AI 接入沿用原项目本地服务，配置百炼 API Key 后才能调用模型。本交付未包含任何密钥。

## 本轮视觉修改

- 顶部标题区取消重复的英文眉题、解释性小字、角落日期和单独的静态插画；采用可交互 Canvas 细线网格、节点粒子和鼠标联动。支持系统减少动态效果设置。
- 左侧五组导航压缩行高、统一选中与悬停背景。选中项没有红色左边框；滚动能力保留但滚动条隐藏。侧栏删除重复的英文介绍与版本提示。
- 账号头像和 AI 形象升级为同一套渐变浮雕视觉；全局 AI 按钮取消快捷键方块。
- 企业画像缩短身份信息、状态说明和技术评价描述，把完整分析保留在业务详情与技术评价页。
- AI 会话增加细腻的等待动画、轻量状态字幕、对话式失败卡片与重试操作。等待文案属于交互反馈；工具执行记录只使用实际 API 返回的事件。费用、积分、耗时、token 用量没有返回时不会伪造。
- 原版证据台账、人工采信、冲突处理、五维评分、专家规则与报告导出仍在。

## 队友内容反馈对应的调整

| 问题 | P8.1 的处理 |
|---|---|
| 北京名录切换行业后无结果 | 改为“方向线索”，对真实 6,190 家企业名称做透明的关键词筛选。八个一级方向均有企业名称命中。真实企业所属行业仍需核实，不将名称推断当成权威行业分类。 |
| 准入演练出现合成企业 | 主要入口调整为“准入核验”，从真实北京企业名录建卷、进入资料解析、证据复核和技术评价。原本的合成样本生成引擎保存在旧版业务备份及现有源代码中，当前主页面不展示模拟企业，也不自动跑模拟批次。|
| 今日待判标签过多 | 只显示简短状态，技术分与等级减少重复标签；队列来源为北京已建卷真实企业，默认依据证据充分度排序。|
| 企业画像小字、防御性说明太多 | 收紧首屏信息，只强调企业、来源线索、当前评价状态；原始研究依据和规则详情继续保留在后续模块。|
| AI 解析目的不明确 | 统一称“资料解析”，用“添加公开资料”作为首要操作；增加 TXT、MD、CSV 文件读取，填入解析正文。来源网址、日期与人工复核流程仍然要求用户提供。|
| Agent 死板、等待枯燥、报错明显 | 交互状态轻量化、轮换等待提示、渐变浮雕 Logo、失败后内联重试与查看详情；保留真实调用、引用、步骤和提案确认。|

## 仍需继续开发的事项

1. **PDF、图片、音频的端到端导入**：本轮仅实现纯文本文件读取；财报 PDF 解析、票据图像识别、语音转写尚未接通。下一轮应实现来源文件保存、逐页/时间戳引用、模型抽取、人工复核后写入台账的闭环，并在获得授权后处理含个人或企业敏感信息的材料。
2. **正式行业分类**：当前名录原始数据无行业字段；名称关键词只是搜索线索。正式分类需要增加来源证据、可编辑分类、人工审核记录、分类置信度和版本。
3. **Agent 真实百炼端到端测试**：本地测试环境未配密钥。可对连接、提问、工具调用、证据引用、导入写入、报告生成和 API 成本记录开展完整验收。以服务端真实 token 用量为准；当前尚无可展示的积分消耗接口。
4. **复杂页面细部文案**：部分专家规则、数据来源及报告管理页面继承 P7.2 的较长说明，后续可以逐模块压缩，但应保留必要的评分边界、审核操作和来源详情。
